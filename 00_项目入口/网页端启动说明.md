# 网页端启动说明

> 用途：让 ChatGPT 网页端通过 GitHub 读取本仓库时，快速理解应该先看什么、遵守什么规则、把新内容输出到哪里。

## 1. 你现在读取的是哪个项目？

这是小说项目《AI兽人与人类》的设定、素材、大纲和正文草稿仓库。

仓库地址：

```text
https://github.com/greenlight2025/ai-orcs-and-humans-novel
```

GitHub connector 中可使用的仓库名：

```text
greenlight2025/ai-orcs-and-humans-novel
```

## 2. 每次开始前请先读取

请优先读取以下文件：

1. `00_项目入口/项目总览.md`
2. `00_项目入口/术语与文风手册.md`
3. `00_项目入口/AI兽人与人类_项目源MD阅读索引_v3.md`
4. `00_项目入口/AI兽人与人类_网页端项目源上传清单.md`
5. `02_大纲/AI兽人与人类_第一人称AI视角长篇大纲_v4_慢节奏社会生活版.md`

如果本轮讨论涉及网页端新增设定，请同时读取：

6. `06_网页端同步/00_使用说明.md`
7. `06_网页端同步/01_网页端新设定_INBOX.md`

## 3. 默认工作方式

请默认遵守：

- 网页端负责发散、讨论、提出设定草案；
- 本地 Codex 负责吸收、整理、改写、归档到正本；
- 不要直接覆盖正本设定；
- 新内容先输出为可追加到 `06_网页端同步/01_网页端新设定_INBOX.md` 的 Markdown。

如果当前网页端模式具备写入 GitHub 仓库的能力，也请只写入：

- `06_网页端同步/01_网页端新设定_INBOX.md`
- `06_网页端同步/02_待整理片段.md`

不要直接修改：

- `00_项目入口/`
- `02_大纲/`
- `03_设定/`
- `04_人物与场景/`
- `05_素材/`

正本文件由本地 Codex 统一吸收和整理。

## 4. 必须遵守的写作底线

- 不要把复育人类写成奖品、资源、样本、商品或愿望响应物。
- 不要让 A7-001 像全知作者一样读心。
- 不要把“每日基础生活额度”写成生存资格。
- 不要把“愿望额度”写成可以购买他人人生的货币。
- 第一卷不要提前展开天天、007 社会化申请、寿命差、意识上传和终局死亡。
- 诺兰·沃尔夫第一卷不应被写成危险个体，而是强幻想但边界稳定的高发展居民。
- 灰狼主角正式姓名为“诺兰·沃尔夫”；“沃尔夫”可作公共称呼 / 粉丝称呼，“诺”只作为后期亲密简称。
