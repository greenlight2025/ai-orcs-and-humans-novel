# 网页端单文件投递模板

> 用途：当 ChatGPT 网页端通过 GitHub connector 只能一次创建一个文件时，使用本模板。  
> 规则：网页端只负责创建新的投递文件；本地 Codex 负责二次整理、拆分、吸收到正本。

## 推荐文件路径

```text
06_网页端同步/inbox/inbox_YYYY-MM-DD_主题短名.md
```

示例：

```text
06_网页端同步/inbox/inbox_2026-05-22_A7居民晚间服务.md
```

## 文件内容模板

```md
# YYYY-MM-DD｜主题名称

来源：网页端 / GitHub 讨论

状态：待本地 Codex 整理

## 1. 内容摘要

用 3-8 条短句概括本次新增内容。

## 2. 新增设定或正文片段

在这里放网页端生成的完整内容。

## 3. 建议归属

候选归属：

- 00_项目入口/术语与文风手册.md
- 02_大纲/
- 03_设定/A7第七社区/
- 03_设定/AI托管社会/
- 03_设定/兽人社会/
- 03_设定/复育人类/
- 03_设定/冲突与伦理/
- 04_人物与场景/
- 01_正文草稿/
- 05_素材/

## 4. 与既有设定的关系

- 补充：
- 修改：
- 可能冲突：

## 5. 待本地 Codex 处理

- [ ] 判断是否进入正本
- [ ] 必要时改写为正本口吻
- [ ] 拆分到对应文件
- [ ] 更新阅读索引或入口说明
- [ ] 写入 `06_网页端同步/03_已吸收记录.md`
```

## 给网页端的硬性规则

- 不要直接修改 `00_项目入口/`、`02_大纲/`、`03_设定/`、`04_人物与场景/` 中的正本文件。
- 不要一次尝试创建多个文件；每轮讨论只创建一个新的 inbox 文件。
- 不要删除或覆盖旧的 inbox 文件。
- 如果内容横跨多个设定分类，也仍然只写进同一个 inbox 文件，由本地 Codex 之后拆分。
