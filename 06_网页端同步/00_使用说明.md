# 网页端同步｜使用说明

> 用途：承接 ChatGPT 网页端通过 GitHub 读取项目后新生成的设定、灵感和讨论结果。  
> 原则：网页端负责发散；本地 Codex 负责吸收、整理、归档到正本。

## 1. 基本流程

推荐流程：

1. 网页端读取 GitHub 仓库中的项目入口文件。
2. 网页端基于入口文件讨论新设定。
3. 网页端输出可追加到 `01_网页端新设定_INBOX.md` 的 Markdown。
4. 将内容提交或复制到本目录。
5. 回到本地 Codex，让我定期整理 INBOX。
6. 已吸收内容记录到 `03_已吸收记录.md`。

## 2. 不要直接改正本

网页端新生成内容不要直接覆盖：

- `00_项目入口/术语与文风手册.md`
- `00_项目入口/AI兽人与人类_项目源MD阅读索引_v3.md`
- `02_大纲/`
- `03_设定/`
- `04_人物与场景/`

原因：

- 网页端适合发散；
- 正本需要统一术语、版本和叙事节奏；
- 直接混入正本容易造成同一设定多版本并存。

## 3. 本目录文件用途

| 文件 | 用途 |
|---|---|
| `01_网页端新设定_INBOX.md` | 网页端新生成的设定、人物、剧情、制度先放这里 |
| `02_待整理片段.md` | 暂时无法归类的灵感、句子、桥段、对话摘录 |
| `03_已吸收记录.md` | 记录哪些网页端内容已经被整理进正本 |
| `04_网页端提示词.md` | 在网页端使用 GitHub 仓库时可复制的提示词 |

## 4. 吸收规则

网页端内容进入正本前，需要检查：

- 是否符合 `术语与文风手册.md`；
- 是否与当前总纲 v4 冲突；
- 是否会提前泄露后续卷设定；
- 是否把天天写成奖品、资源或愿望响应物；
- 是否让 A7-001 像全知作者一样读心；
- 是否与已有 A7 场景、居民样本、Wolf 设定冲突。

## 5. 推荐追加格式

每次从网页端带回内容时，建议使用：

```md
## YYYY-MM-DD｜主题名称

来源：网页端 / GitHub 讨论

### 内容摘要


### 原始片段


### 可能归档位置


### 待确认问题


```
